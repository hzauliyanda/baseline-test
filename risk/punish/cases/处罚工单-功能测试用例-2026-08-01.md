# 风控处罚工单（punish / 预警工单）功能测试用例

生成时间：2026-08-01
模块：风控-处罚/预警工单（IssueType=PUNISH / SubIssueType=OTHER）
系统：test-risk.inshopline.com
数据来源：master 源码 + CDP 探索 + 接口实跑（storeId=1113/riskType=EMAIL_ERROR）
TC-ID 前缀：PN

> 三层数据：Issue(工单) + PunishInfo(处罚主体 store/product) + MarkRecord(标注记录)。状态：5待下发→6标注中→7标注完结；not-deliver→11。

## 处罚工单创建模块

### P0 测试用例

#### TC-PN-001: 创建处罚工单（含处罚主体）
**优先级**：P0
**描述**：RISK_OPERATOR 创建，riskInfoList 含 store 处罚主体
**步骤**：POST /add，riskInfoList [{subjectType:store, fieldInputType:TEXT, riskValue:storeId, riskType}]
**预期**：成功返回 issueId；状态=5待下发；PunishInfo 落库；通知人合并去重
**实现参考**：addWithoutAuth → buildPunishSubjectListCommon 解析 riskValue（TEXT 逗号拆分）→ enrichPunishInfo RPC 补全。

## 状态流转汇总
```
新建 ──▶ 5待下发 ──deliver──▶ 6标注中 ──截止到期──▶ 7标注完结
   │   │                       │
   │   ├──not-deliver/batch────▶ 11无需下发
   │   └──batch/delete(删punish记录，仅5)
   └──edit/riskInfos(仅5)
备注仅7；暂缓6写MarkRecord；subject/info≠5；删除base(admin任意/本人+3/5)
```
