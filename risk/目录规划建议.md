## 现有模块迁移方案

| 现有目录 | 建议迁移到 | 说明 |
|---|---|---|
| `risk/normal-work-order/` | `risk/管控合作/normal-work-order/` | 保留完整结构，外层加一层 |
| `risk/punish/` | `risk/处罚中心/punish/` 或改名 `penalty-event/` | 对应「处罚下发/处罚明细」 |
| `risk/complaint/` | `risk/处罚中心/complaint/` | 对应「申诉处理」 |
| `risk/threathunter/` | `risk/分析中心/threat-hunter/` | 对应分析中心里的威胁猎人情报查询接口 |

> **不建议强制立即迁移**：现有满配样例 `normal-work-order` 跑通中，改路径会影响 skill 脚本里的硬编码路径。`_toolkit/` 的去硬编码已完成，但 `~/.claude/skills/api-flow-recorder/` 内的 `cdplib.py`、`tail_api.py` 等 5 处仍有 `ROOT=~/baseline-test` 写死——等这 5 处改成读配置或环境变量后再整体迁移更稳妥，否则需要同步手改 skill 包路径（见 `_toolkit/去硬编码进度.md` ⬜ 待做部分）。

## 优先级建议（按测试价值排序）

### 第一批（核心业务流程，高价值）

| 模块 | 推荐理由 | 参考样例 |
|---|---|---|
| 处罚中心 | 现有 punish/complaint 已有半配，合并补全 | normal-work-order |
| 策略中心 | 风险决策核心，子功能多（8个），覆盖面广 | — |
| 审核中心 | 审核任务涉及商品/店铺/内容/资质四条线 | — |
| 管控合作 | 普通工单已满配，补预警处理等子功能 | normal-work-order |

### 第二批（数据链路，中等价值）

| 模块 | 推荐理由 |
|---|---|
| 名单管理 | 名单库/名单应用，接口边界清晰 |
| 规则中心 | 配置类，接口可信断言容易 |
| 反馈中心 | 反馈事件 + 侵权投诉，有外部输入边界 |
| 知识库 | 样本包/词库等资产类，数据量大但接口简单 |

### 第三批（工具/平台型，验证难度高）

| 模块 | 推荐理由 |
|---|---|
| 分析中心 | 含威胁猎人，接口多但多为只读查询 |
| 设备指纹 | 指标监控类，DB验证困难 |
| 配置管理 | 研发配置类，环境依赖强 |

## 每个模块的目录模板

```
risk/<模块名>/
├── _meta.yaml            # 模块元信息（URL、仓库、负责人）
├── 功能地图.md           # 该模块的完整功能场景（从系统功能地图细化）
├── auto/
│   ├── api/             # 接口 flow yaml + runner
│   └── ui/              # TS Playwright 用例
└── docs/
    ├── functional-cases/ # 功能用例
    ├── ui-cases/         # UI 用例
    ├── checklists/       # 人工校验清单
    └── reports/          # 回归报告
```

## 备注

- 目录名使用**中文**（与系统显示名一致），便于对照查找；英文子目录按功能命名（如 `normal-work-order`）
- `_meta.yaml` 里的 `module_base_path` 填对应的 URL 路径段
- 系统功能地图中标注 ▸ 的子菜单项有二级展开，建议在各模块的 `功能地图.md` 中细化
