# 普通工单 · 人工校验清单

> 普通工单模块**唯一**的人工核对清单（2026-08-02 合并原「手动覆盖清单」而成）。
> - 🟡 **DB 校验段**：由 5 份 flow yaml 的 `db_check` 自动抽取（改 yaml 后可重生成此段）。
> - 🔴 **人工覆盖段**：按 Tier 人工整理（含补齐建议），**手动维护，勿被 🟡 的重新生成覆盖**。
> 配套自动跑：模块根目录 `runner.py auto/api/flow-xxx.yaml`（🟢 assert 段 runner 判死）。

## 用法
1. 先跑自动：每份 flow 的 🟢 assert 由 runner 评分，全绿才继续看本清单。
2. 🟡 **DB 校验**：用执行输出里的 `run_id` / 提取到的 `issue_id`（或 config/notify id）替换 SQL 里的 `<...>`，在**有授权的 DB 环境**逐条跑，比对「期望行」。任一不符=该 case 真伪不成立，即便接口返 SUCCESS。
3. 🔴 **纯人工**：runner 跑不了（跨系统/越权/并发/上传），按说明人工执行并勾选。
4. 每轮回归：🟢机器 + 🟡SQL + 🔴人工 三桶**都过**才算这条真的成功。

**规模**：🟡 DB 校验 61 条 SQL ｜ 🔴 人工 29 项

## 建议（补齐优先级）

1. **优先补 Tier 3**：只差几个 id，补 `--set` 后 negative + paths 覆盖率能从 ~70% 拉到 ~90%。
2. **Tier 2 一次投入长期收益**：搞一个 NORMAL_USER 账号 cookie 进 `risk/_env.yaml`，权限/越权类负向以后都能自动回归。
3. **Tier 1 三类**（文件上传、并发锁、跨系统副作用）登记为固定人工/压测项，每轮回归过一遍。
4. **静默漏洞 `neg_save_primary_empty_silent`（主键空不落库 save:920）**：能自动跑，但它验的是**代码漏校验**——空主键被静默存成 `''`（🟡 段 `create` 的 field_value db_check 正是查这个）。建议**同时提代码单修复**，而非仅记录。
