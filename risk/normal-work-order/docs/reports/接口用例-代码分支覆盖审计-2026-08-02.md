## 一、结论（一句话）

**现有 65 step 覆盖了「运营视角的全端点 happy-path + 7 条业务负向」，但「入参为空 / 必填字段缺失 / id 非数字 / 枚举非法值 / 越权可见」这一整类负向 ≈ 0 覆盖，共梳理出 50+ 个未覆盖守卫分支。** 你问的"入参为空的场景"正是最大空白。

### 已覆盖的 7 条业务负向（现有用例打到的）
| 负向 | 用例 | 代码位置 |
|---|---|---|
| 非当前审批人审批 → NO_AUTH | approve_no_auth | save:334 |
| 审批 approveStatus 传 ABC → 走通过（未严格枚举校验） | approve_status_anything | save 审批分叉 |
| 非末级审批人改抄送 → ISSUE_CANNOT_MODIFIED | edit_not_last_approver | save:1724 |
| OTHER 类型不触发名单同步 → ISSUE_TYPE_ERR | approve_notify_retry | save:112 |
| 通知配置 riskType 失效 → 无效的风险类型 | notify_detail | notify_svc:127 |
| 建模板运营地区重复（备注断言） | config_save_area_repeat | controller 层 |
| 非运营建模板 → NO_AUTH（skip 未实跑） | config_save_no_auth | config_ctrl:239 |

### 覆盖率画像（负向维度）
- **业务状态门/权限门**：部分覆盖（单级 SINGLE 审批链、删除、非末级编辑）
- **入参为空/required 缺失**：❌ 0 覆盖
- **id 非数字/不存在/=0**：❌ 0 覆盖
- **枚举非法值**（issueType/punishSubIssueType/category）：❌ 0 覆盖
- **越权可见范围**（普通用户过滤、他人工单名单不可见）：❌ 0 覆盖
- **MULTI 多级/会签审批链**：❌ 0 覆盖
- **submitType=SUBMIT 草稿暂存链**：❌ 0 覆盖

### ⚪ P3 — 静默行为 / 内部同步（无独立端点，建议单测或标注）

- `save:920` 主键 `fieldValue==""` **静默 continue 不落库**（潜在漏校验，值得补一条验证静默行为的用例暴露风险）
- `base_svc:131` QueryMerchantInfo 主键值/字段名空 → 静默 nil；未知 fieldName 兜底
- `del_data_query:122` namelistCode 空 → error（名单剔除同步内部，建议单测）
- 约 30 处 `if err!=nil → GET_DETAIL_ERROR/SYSTEM_ERROR` DB/RPC 异常传播：接口用例难稳定构造，归为基础设施容错，不逐条补

### 说明：cookie 会话必填（低优先，同类一条打通）
`AppId/UserId/OperatorId` 等 23 处 `binding:required` 在正常鉴权流恒存在，只需构造 1 条「删 Cookie」用例即可代表整类 400，不必逐端点补。
**注意代码缺口**：`normal/save`、`normal/approve`、`notify/config/save` 的业务字段（issueName/issueId/taskTame 等）**没有 binding:required**，空值不会被 controller 挡下，会穿透到 service——这本身是代码校验薄弱点，补空值用例可暴露实际行为。

**分档小结**：
- **Tier 1 架构做不了（2）**：文件上传 multipart、并发锁 → 固定手动/压测项。
- **Tier 2 需 NORMAL_USER 账号（4）**：config NO_AUTH、越权查名单、普通用户角色/可见范围 → 建议把普通用户 cookie 写进 `risk/_env.yaml` 长期复用。
- **Tier 3 需前置数据 --set（其余）**：处罚模板id、自有待审工单id、二级审批人id、品牌真实字段 → 给值即自动跑。

**跑法**：`RISK_COOKIE=$(cat /tmp/risk_cookie.txt) python3 <skill>/scripts/runner.py flow-negative.yaml`
**约定**：负向 assert 暂锁 `status:200`，期望错误码写在注释；**首次实跑后按真实 `$.code`/`$.message` 回填精确断言**（沿用基线"跑完核对返回值"惯例）。
**注意**：`neg_save_primary_empty_silent`（save:920 主键空不落库）验证的是**代码漏校验**，建议同时提代码单修复。
