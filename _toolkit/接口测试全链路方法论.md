## 三、skill 评估与建议

### 3.1 现有 skill（够用，保留）
- **p2-test-case-generator**：功能用例生成，增量增改模式好，xlsx 导出。✅ 不改
- **p3-ui-test-case-generator**：UI 场景 YAML 生成，TC-ID 追溯。✅ 不改

### 3.2 要优化的 skill

**api-flow-recorder（重点优化）**：
- 集成 `cdp_type.py` 到 `scripts/`（antd 受控输入+中文，探索时反复用到）
- `recorder.py` 加 ws 自动重连/心跳（当前约 2 分钟超时断开，要手动重启）
- 加 antd 操作 helper 到 `references/`：mousedown 打开 Select、.ant-modal 作用域定位、tags 回车确认、id 冲突处理
- 加"爬列表建真实数据池"的标准流程到 `references/`

**p4-browser-test-runner-devtools（优化）**：
- 支持自定义 CDP 端口连接（当前只支持 chrome-devtools MCP，这次 MCP 没连上，用自写 ui_runner.py 替代）
- 或支持直接用 cdp.py 驱动（复用 api-flow-recorder 的持久化 Chrome）

### 3.3 要新增的 skill

**octopuses-upload（新增）**：
- 创建用例：`POST /api/autotest/cases/case`（完整 body）
- 用例归目录：`POST /api/autotest/dir/node` nodeType=CASE（**关键：不是 pid 字段，是单独建 CASE 节点**）
- 移动用例：`PUT /api/autotest/dir/node/order`
- 创建目录：`POST /api/autotest/dir/node` nodeType=DIR
- 参数：access-token/space-id/groupId/pid/creator
- 读 flow.yaml → 批量上传 + 归目录

## 四、关键参数与坑（可复用到其他系统）

### 4.1 鉴权
| 系统 | 鉴权 | 提取方式 |
|------|------|---------|
| test-risk（被测） | Cookie（riskSessionId+armorSession）+ appId/version 头 | CDP `Network.getCookies` → 整段存文件 |
| octopuses（平台） | access-token（header）+ space-id | 用户提供（固定） |

### 4.2 真实数据获取（绕过"测试环境无数据"）
- **爬列表**：`POST /xxx/list` 多页 → 提取已有数据的真实 ID/主键
- 普通工单示例：storeHandle=liyanda6、merchantId=li0106@123.com（爬 normal/list 的 primaryInfo）
- 处罚工单示例：storeId=1113、riskType=EMAIL_ERROR（爬 punish/store/list）

### 4.3 antd 后台操作坑（必踩）
| 坑 | 解法 |
|----|------|
| Select 普通 click 不打开 | `.ant-select-selector` 派发 mousedown+mouseup |
| 弹窗字段 id 与列表冲突 | `.ant-modal` 作用域定位，或先 eval 打独立 id |
| React 受控输入合成 fill 不进 state | CDP `Input.insertText`（中文必须 insertText，dispatchKeyEvent 不支持中文）|
| tags 输入 | insertText 后元素上 dispatch Enter |
| recorder ws 超时 | 关键抓包前 `nohup recorder.py &` 重启（追加写不丢）|

### 4.4 接口用例参数化
| 类型 | 处理 |
|------|------|
| cookie | `${RISK_COOKIE}`（平台环境变量） |
| base_url | 写死测试环境（切环境批量替换） |
| 新建实体名 | `[FLOW]{{run_id}}`（run_id 自动注入时间戳） |
| 链式依赖 | `extract issue_id: $.data.issueId` → 后续 `{{issue_id}}` |
| issueId 类型坑 | save 返回数字，edit/approve 要 string → detail extract 字符串覆盖 |

### 4.5 octopuses 平台坑
| 坑 | 解法 |
|----|------|
| 用例不归目录（pidList=None） | **不是 pid 字段**，要单独 `POST /dir/node` nodeType=CASE 建 CASE 节点 |
| PUT 改 pid 撞乐观锁 | node/order 移动（但要求 CASE 节点已存在）|
| 新建目录无效 | API 建的目录节点 vs 用例 pidList 是两套（但 CASE 节点能归）|
| 删除接口没找到 | UI 手动删 |

## 六、复用到其他系统/模块（Checklist）

### 6.1 可直接复用（不改）
- cdp_type.py（antd 输入助手）
- ui_runner.py 的 helper 函数集
- runner.py + flow.yaml 参数化结构
- upload_cases.py / move_cases.py（上传+归目录）
- 四阶段方法论

### 6.2 按系统替换
1. `base_url` + 路径前缀（如换成其他产品域）
2. Cookie（重新 CDP 提取）
3. 爬该模块列表拿**该模块的真实数据池**
4. 读该域 `router` → 接口全集；Agent 读 service/vo/enum
5. flow-all-types 的枚举类型换成该模块的
6. octopouses 上传参数（access-token/groupId/pid 可能换）

### 6.3 标准 7 步流程
```
1. launch_chrome + recorder + cdp 探索 → 功能地图 + 抓包
2. CDP 提 cookie / 爬列表拿真实数据池
3. 读 router + 3 Agent 读 service/vo/enum → 接口差距 + 分支清单
4. 编 flow.yaml(主链路) + flow-supplement(漏接口+负向) + flow-all-types(枚举覆盖)
5. runner 跑接口全绿（先 dry-run，再实跑，自建自删零残留）
6. ui_runner 跑 UI 场景 + 截图
7. upload_cases + 建 CASE 节点归目录到 octopuses
```
